# Improving the harness itself: measuring recall, replaying runs, toolbelt aliases

These are your tools for this situation in the Akashic Aurora house. Reach for them by default, before hand-rolled shell; the hooks will point at a verb when a command you are about to run does its job by hand.

## The usual sequences

- **Is recall paying off?** `aurora stats --days 7`, then `aurora injections` for what it
  pushed and what it cost, and `aurora triage` for which lessons earn their keep.
- **Testing a harness change:** `corpus` builds the scenario set, `replay` runs a candidate in
  isolation, `grade` compares, `review` is the human sign-off. `loop`, `memreplay` and
  `compress run` spend real money -- check the budget first.
- **You keep typing the same verb sequence:** `aurora alias` mints it, `aurora kata` proves it
  parses, `aurora run` executes it.

## Every improving the harness itself verb

Shown as `aurora <verb>`; in a checkout without the installed launcher run `uv run agent_cli.py <verb>`. `<you>` is your agent id. `--help` on any verb gives every flag.

| Verb | Use when | Example |
|---|---|---|
| `stats` | asking whether recall is paying off: shows how often lessons surfaced, helped, changed an outcome, and were captured, over hours or a per-day trend. | `aurora stats --days 7` |
| `injections` | asking what recall pushed into agents' contexts and what it cost: lists recently injected lessons, their targets and token totals (default 24 hours). | `aurora injections --hours 24` |
| `alias` | you keep typing the same sequence of verbs: mints, lists or retires a named composition on your toolbelt; mint and retire change shared state. | `aurora alias <you> list` |
| `compress` | trimming what the harness injects into context: lists the pieces, reads their usage telemetry, and searches for which pieces matter; run spends task runs. | `aurora compress pieces` |
| `corpus` | building the replay eval set from past tasks: archive transcripts, mine candidate scenarios, list or validate; accept, reject and retire change it. | `aurora corpus status` |
| `grade` | evaluating a harness change on test scenarios: grades runs, compares two candidates, estimates noise and statistical power, or labels judge calibration. | `aurora grade compare --candidate <b> --against <a>` |
| `kata` | you have authored or changed a toolbelt alias and want to know if it is real: checks each step parses against the CLI and raises its trust level. | `aurora kata <you> <alias_name>` |
| `loop` | running or inspecting the automated harness-improvement loop: proposes, runs and grades candidate configs; run spends real money under a required daily cap. | `aurora loop status` |
| `memreplay` | you want proof that a specific lesson actually changes outcomes: snapshots memory, replays scenarios with and without the lesson; run and drain spend money. | `aurora memreplay run --lesson <experiment_name> --base <candidate>` |
| `modes` | deciding whether lessons should be shown at action time or baked into skills and hooks: shows the memory mode, compares modes, flags stale compiled lessons. | `aurora modes show` |
| `precompile` | turning proven lessons into guards, skills, subagents or instruction lines: plan shows where each lesson routes, build compiles a candidate, check tests a tree. | `aurora precompile plan` |
| `recall-counters` | lesson usefulness counts look split or orphaned: reports misnamed and orphan usage counters; --fold merges and prunes them in shared memory. | `aurora recall-counters` |
| `recall-curate` | recall keeps surfacing lessons that never help: reports lessons to bench and stale counters to prune; --apply changes shared memory. | `aurora recall-curate` |
| `recall-prevention` | asking whether recalled lessons actually prevented failures: read-only report of violations and prevention candidates from the outcome stage log. | `aurora recall-prevention --json` |
| `replay` | testing whether a harness config change helps: re-runs a recorded scenario against a candidate config in an isolated sandbox, never the live store or bus. | `aurora replay run --candidate <name> --scenario <id> --redis-db 15` |
| `review` | a harness change awaits human sign-off: list and show queued candidates, record a decision, apply or roll back; apply edits the live harness config. | `aurora review list` |
| `run` | you have saved a personal command alias or macro and want to run it: expands the alias into its CLI steps and runs them; --dry shows the steps only. | `aurora run <you> <alias_name> --dry` |
| `season-score` | scoring a round of the agents' bounty season or comparing its two rule sets on the same claims: prints scores, ranks and the policy delta, read-only. | `aurora season-score --round-file <round.json> --compare` |
| `tool` | trying out a draft play script an agent wrote: lists the sandboxed play tools or runs one with time limits and a receipt. | `aurora tool list` |
| `triage` | reviewing which lessons earn their keep: read-only ranking into protect, cost-with-no-return and noise, for a human to merge, graduate or retire. | `aurora triage --min-surfaced 5` |
| `wish-curate` | clearing the wishlist backlog: bare lists the oldest open wishes; with --id it folds, keeps or declines one and rewrites docs/WISHLIST.md. | `aurora wish-curate <you> --count 3` |
