# Fleet health and setup: is everything running, why is a seat stuck, hooks, grants, secrets

These are your tools for this situation in the Akashic Aurora house. Reach for them by default, before hand-rolled shell; the hooks will point at a verb when a command you are about to run does its job by hand.

## The usual sequences

- **An agent is stuck or silent:** `aurora unwedge <agent>` diagnoses (read-only, recommends a
  fix). The whole fleet at a glance: `aurora flightdeck`; progress, not mere presence:
  `aurora doctor`.
- **Is shared memory up?** `aurora status`.
- **Recall or other hook output missing or noisy:** `aurora hooks status`, then `install`,
  `enable` or `disable` -- never hand-edit settings files.
- **The human must give you a key or password:** `aurora secret` opens a paste window that
  writes to the vault, never the transcript.
- **Shared-state controls** -- `bifrost-pause`, `bifrost-resume`, `bifrost-drain`,
  `bifrost-skip-to-now`, `grant`, `gateway restart`, `stand-down` -- change things for the whole
  fleet. Use them only when the situation in their line is actually true, and say you did.

## Every fleet health and setup verb

Shown as `aurora <verb>`; in a checkout without the installed launcher run `uv run agent_cli.py <verb>`. `<you>` is your agent id. `--help` on any verb gives every flag.

| Verb | Use when | Example |
|---|---|---|
| `status` | asking whether shared memory is up and healthy: shows the storage backend, lesson and key counts, and whether logging paths are silently degraded. | `aurora status` |
| `doctor` | the fleet seems stuck or slow, or after deploying to a machine: grades each agent's progress (wedged, stalled, frozen) and services; --deploy checks a machine. | `aurora doctor` |
| `unwedge` | an agent seems stuck, silent or not answering: read-only diagnosis combining runner, lanes, backlog and locks into a verdict and recommended fix. | `aurora unwedge <agent>` |
| `flightdeck` | you want the whole fleet on one page: combines agent health, pressure, lane health, locks and recent commits; --agent drills into one seat. | `aurora flightdeck` |
| `hooks` | recall injections or other harness hooks are missing, noisy or need switching: shows hook wiring and installs, removes, enables or disables it; edits settings. | `aurora hooks status` |
| `secret` | the human needs to give you an API key or password: opens a paste window that saves it to the vault, never the transcript; bare lists which exist. | `aurora secret` |
| `setup` | setting Aurora up on a new machine or for a new harness: wires hooks, agent id, MCP and git hooks; writes config, so try --dry-run first. | `aurora setup --dry-run` |
| `bifrost-drain` | a bus runner must be restarted without losing in-flight work: asks it to finish its current message, release its lock and exit; changes runner state. | `aurora bifrost-drain <you> --to <runner_agent> --reason "<why>"` |
| `bifrost-pause` | the human must barge in and the whole fleet should stop: freezes every bus auto-responder, changing shared state (--soft lets work finish); set --ttl. | `aurora bifrost-pause --soft --ttl 600 --reason "<why>" --by <you>` |
| `bifrost-resume` | the bus was paused and seats should pick up work again: unfreezes the bus auto-responders; changes shared state for the whole fleet. | `aurora bifrost-resume` |
| `bifrost-skip-to-now` | an agent is stuck replaying an old message backlog and the bus is already paused: jumps its cursors to now, dropping unread mail; audited, changes shared state. | `aurora bifrost-skip-to-now <agent> --by <you> --reason "<why>"` |
| `boop` | you just want to confirm the command door answers at all, or a quick look at what is going on around you with --surface: always replies, changes nothing. | `aurora boop --surface --agent <you>` |
| `discord` | the human wants fleet updates on their phone: status shows the outbound Discord webhook setup; test and send post real messages to the channel. | `aurora discord status` |
| `fleet` | you want a local Ollama model: lists the local model roster, picks one for a capability and memory budget, or calls one once with a prompt. | `aurora fleet select --capability summarize --max-vram 12` |
| `friction` | asking how well a seat's asks get answered: read-only report of open, answered and dead asks, dead rate and time to settle over the last week. | `aurora friction <you> --window-h 168` |
| `gateway` | Discord messages from the operator are not reaching the fleet: status shows the inbound Discord gateway; restart kills and relaunches it, changing live state. | `aurora gateway status` |
| `grant` | a seat needs a capability or role changed: mints, revokes or lists access grants with a reason and time box; admins only, and it changes shared access. | `aurora grant --list` |
| `harnesses` | asking what your harness (Claude Code, Cursor, Codex, bare CLI) actually supports here, like hooks or automatic recall: prints the capability matrix. | `aurora harnesses` |
| `kit` | a seat needs the standard recovery shortcuts for wake loops and stalls: --show previews the kit; without it, installs the bundle onto that seat's toolbelt. | `aurora kit <you> --show` |
| `link` | connecting this fleet to another fleet: identity, invites, joining, membership, sync and cross-fleet mail; invites, joins and removals change shared state. | `aurora link status` |
| `provenance` | you need to know which harness, model, effort and environment a session runs under: shows the session's provenance record, writing it if missing. | `aurora provenance --json` |
| `pulse` | asking where work is piling up across the fleet: read-only pressure map of each seat's backlog, sorted into critical, elevated and normal zones. | `aurora pulse` |
| `reentry` | the human operator returns and asks what they missed: renders what moved since their last word and their one open question, quoted verbatim. | `aurora reentry` |
| `resident` | naming, showing or placing a long-lived agent identity: manages resident callsigns and adjudicates their verdicts; ratify is human-only and writes. | `aurora resident show <callsign>` |
| `watch` | starting a long run that must not die silently: declares it so silence raises an alarm, checkpoints while alive, and stands down when done. | `aurora watch <you> --declare "<what is running>" --grace 1800` |
