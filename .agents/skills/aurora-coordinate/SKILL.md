# Working alongside other agents: mail, locks, tasks, who is doing what

These are your tools for this situation in the Akashic Aurora house. Reach for them by default, before hand-rolled shell; the hooks will point at a verb when a command you are about to run does its job by hand.

## The usual sequences

- **Start of a turn:** `aurora bifrost-sync <you>`. Act on what needs acting on, then
  `aurora bifrost-ack <you> <msg_id> --note "..."` -- reading alone does not count as handled.
- **Before editing a file other seats may touch:** `aurora locks` first; if it is free,
  `aurora lock <you> <path>`, edit, then `aurora unlock <you> <path>`. The pre-edit hook warns on a
  held lock, but only a claimed lock warns the *other* seat.
- **Before starting a slice:** `aurora scout "is anyone mid-flight on <area>?" --by <you>` and
  `aurora task next`. Claim it with `aurora task claim` so the ledger, not a chat message, says
  who owns it.
- **Talking to a peer:** `aurora bifrost-send <you> --to <agent> --kind request --text-file msg.txt`.
  Use a text file for anything long or starting with a dash. A clipped message: `aurora capture`;
  a spilled payload ref: `aurora bifrost-fetch`.
- **You lack a permission:** `aurora defer` queues the command for a seat that has it; do not
  ask the human to run it by hand unless it is theirs to run.
- **End of a turn when you should be reachable:** run `aurora bifrost-standby <you>` as a
  background task. It is not self-renewing: re-arm it after every exit.

## Every working alongside other agents verb

Shown as `aurora <verb>`; in a checkout without the installed launcher run `uv run agent_cli.py <verb>`. `<you>` is your agent id. `--help` on any verb gives every flag.

| Verb | Use when | Example |
|---|---|---|
| `bifrost-sync` | starting a turn or when someone may have messaged you: shows presence and unread bus mail without consuming it; --consume marks it read. | `aurora bifrost-sync <you> --digest` |
| `bifrost-send` | you need to tell, ask or answer another agent: sends a message on the bus; use --text-file for long or flag-like bodies; directed asks arm a reply deadline. | `aurora bifrost-send <you> --to <agent> --kind request --text-file <msg.txt>` |
| `locks` | about to edit a shared file while other agents are live, or asking who is editing what: lists held advisory path locks with holder and age. | `aurora locks <you>` |
| `lock` | you are about to edit a shared file while other agents are live: claims an advisory lock on the path so others see it; unlock when done. | `aurora lock <you> <path/to/file>` |
| `unlock` | you finish editing a path you locked: releases your advisory lock so peers can edit it; you cannot release another seat's lock. | `aurora unlock <you> <path>` |
| `bifrost-standby` | ending a turn and you should wake on new mail: drains the inbox, reports, then blocks as the wake listener; run it as a background task. | `aurora bifrost-standby <you>` |
| `bifrost-ack` | you have handled a bus message addressed to you: records durably that you acted on it (reading alone does not); only the addressee can ack. | `aurora bifrost-ack <you> <msg_id> --note "what was done"` |
| `scout` | about to start work and unsure if a seat is already on it or it was done: a resident model reads ledger and locks, answers, and files a verdict. | `aurora scout "is anyone mid-flight on <area>?" --by <you>` |
| `task` | proposing, claiming, finishing or listing shared work items, or asking what to do next: manages the task ledger lifecycle; most subcommands change shared state. | `aurora task next` |
| `capture` | a bus message looks truncated or you need its exact text: reads the full message by stream id or a sender's latest, optionally saving it verbatim. | `aurora capture --from-agent <peer> --count 3` |
| `defer` | you need a command run that your seat lacks permission for (exec, write, network): queues it for a capable seat; --done with a receipt discharges it. | `aurora defer <you> "<command>" --needs exec --why "<what it unblocks>"` |
| `bench` | stale asks clog your inbox: lists, parks or unparks messages so fresh mail flows; parked mail is kept and its sender notified, so park changes shared state. | `aurora bench <you> list` |
| `bifrost-fetch` | a bus message was clipped or says its payload spilled to a blob ref: fetches the full stored body by its ref. | `aurora bifrost-fetch --get blob:<sha>` |
| `bifrost-nudge` | one specific peer must look at something now or adjust course: sends a targeted interrupt, steer or inform signal; interrupt drops its current work. | `aurora bifrost-nudge <you> --to <peer> --mode steer "<what to look at>"` |
| `focus` | starting or finishing work on a specific ledger task: checks this session in so tool calls and cost are attributed to it; --clear checks out. | `aurora focus <you> --set <task id>` |
| `followup` | a verdict or report leaves a question its author must answer: appends the question to its open questions and queues it for that seat; writes both. | `aurora followup <you> --on <verdict-file> --to <seat> --ask "<question>"` |
| `mailbox` | you need one bus message's full state or to declare act/decline/defer on it: shows body, readers and intent; --retire-ghosts --apply writes declines. | `aurora mailbox <you> --state <sha>` |
| `reply` | answering the human operator over the bus or Discord: sends your reply in one argument and says honestly whether delivery failed; sends a message. | `aurora reply "<answer>"` |
| `roster` | asking which agent seats are actually alive and working right now: lists each seat's proven liveness; --reap re-homes mail stranded on dead seats. | `aurora roster --by-agent` |
| `seat-identity` | hooks, locks or the roster call you by the wrong agent name: shows or binds this session's seat id, which beats the shared environment variable. | `aurora seat-identity <you>` |
| `stand-down` | this session is retiring and a successor must take your agent's seat: permanently yields the seat for this session, no reclaim; changes shared seat state. | `aurora stand-down <you>` |
