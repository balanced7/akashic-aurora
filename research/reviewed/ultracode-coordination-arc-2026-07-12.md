## SYNTHESIS -- unified coordination-layer design

**UNIFIED COORDINATION-LAYER DESIGN — T036→T039 (the "twin-safe consumer" arc)**

### FENCE BRIEF (blind, for deepseek)

BLIND DESIGN BRIEF — coordination layer for concurrent same-identity agent sessions. Design independently; do not assume any particular fix.

CONTEXT: Akashic Aurora is a memory substrate where multiple AI agent sessions share one Redis-backed message bus (repo E:/AI-Setup, seams in core/comm/: bus.py, runner_lock.py, wake_seat.py; hooks in scripts/hooks/claude_stop.py; watcher scripts/bifrost_wake.py; consumer path agent/bifrost_pull.py). The bus gives each agent id a directed inbox stream, a broadcast stream, a single-consumer 'seat' (a Redis lease with a monotonic fencing generation), and a per-agent read cursor. A 'wake watcher' process arms a blocking read and fires when new mail arrives; a stop hook refuses to end a session unless that session has a live armed listener. Trace narration, control/interrupt signals, and real work mail all currently share ONE broadcast stream and ONE cursor.

THE INCIDENT (live, reproduced): Three agent sessions launched with the SAME agent id ('claude') and, in the failure, the SAME inherited session id. Observed consequences: (1) They shared one inbox, one consumer seat, one cursor. The seat's re-entrancy check compares only the session TOKEN (the stored process pid is written but ignored), so same-token co-tenants are ALL treated as re-entrant holders — the single-consumer fence became a no-op and twins co-consumed the shared cursor (twin-eats-mail). (2) A session that did NOT hold the seat was still forced by the stop hook to keep an armed listener; its watcher re-seeded its detection cursor from the shared cursor (which it could never advance, since a non-holder degrades to a non-consuming peek), so it insta-fired on the same static backlog every cycle → arm/insta-exit/stop-hook-re-demands-a-listener loop, 40+ cycles, a full session lost. (3) Auxiliary runner processes spawned near a session inherited that session's id and claimed seats/locks indistinguishably from the session itself.

YOUR TASK: Design the coordination mechanism(s) that make this system correct and non-looping when N sessions share an agent id and possibly a session id. Address all four sub-problems and their interlocks:
 (A) Consumer-seat / identity: how is 'the one consumer' elected and identified so that co-tenant twins (and inherited-id runner processes) cannot all pass the re-entrancy check? What is the identity unit?
 (B) The stop-hook / wake ceremony loop: how does a non-consumer session end cleanly without going dark for the agent id, and without busy-firing on a backlog it can never consume?
 (C) Stream/cursor/wake amplification: should display-trace, interrupt-signals, and work mail share one stream/cursor/wake read-set? If you separate them, name every coupling (presence heartbeats, doorbell pub/sub channels, salient-message promotion) that a naive split would silently break.
 (D) Work-split negotiation (optional layer): if sessions negotiate who does which unit of work, what invariant guarantees exactly one holder per unit — and does that invariant survive two processes sharing the same identity token?

CONSTRAINTS/BAR: Prefer reusing existing seams (name them) over new primitives; state the PRE-REGISTERED failing tests that would gate each mechanism; name the NEW failure modes each introduces; and for EVERY collision-detection or 'am I alone / am I the consumer' check you rely on, state explicitly what it returns when two live processes share the same agent id AND session id — because that is the exact condition the incident creates, and any check that reads as 'self/re-entrant/solo' under it is a latent guarantee-of-collision. ## DESIGN T038 — Work-token negotiation protocol (design only)

MECHANISM: WHAT IT IS. A thin, validated FSM that turns a work split into a first-class, leased, negotiable object — a "work-token" — composed almost entirely from existing seams. Zero new transport, zero new lease/fencing/deadline machinery; the only genuinely new artifact is a small state table + gate functions plus a git-durable record file, deliberately cloned from core/coord/task_ledger.py so the gate discipline is identical.

STATE MACHINE (new module core/coord/work_token.py; mirrors task_ledger.TRANSITIONS/transition()).
Token states + legal moves:
  OFFERED   -> {ACCEPTED, COUNTERED, WITHDRAWN, EXPIRED}
  COUNTERED -> {ACCEPTED, COUNTERED, DECLINED, EXPIRED}   # only while round < N (N=2)
  ACCEPTED  -> {HELD}                                     # accept is a commit; holder then claims the lease
  HELD      -> {RELEASED, EXPIRED}
  RELEASED  -> {}                # terminal; scope enters GRACE (see below)
  EXPIRED   -> {}                # terminal + LOUD; scope re-offerable after GRACE
  WITHDRAWN -> {}               # offerer pulled it before accept
  DECLINED  -> {}               # negotiation_dead: rounds exhausted or empty-counter
A token record: {token_id(=flow id), scope, offerer, holder, state, generation, round, counters[], idempotency_key, seen_keys[], deadline_ts, progress[], directive, history[], grace_until}. Persisted to state/coord/tokens.json via the exact atomic-write+Redis-mirror pattern in TaskLedger.save()/_mirror() (git file is truth; Redis a fail-open read cache). transition() is the one guarded mutation, appending to history[] and rejecting illegal moves with a gate-naming error, byte-for-byte the task_ledger idiom.

GATES (each enforced deterministically in code, task_ledger-style — no model in the loop):
1. COLLISION-POSSIBILITY GATE (zero ceremony when solo). Before any bus round, should_negotiate(scope) checks: (a) Bus(agent).presence() shows >1 live agent, OR (b) a live token/lock/intent intersects scope. If solo AND no intersecting live claim, OFFER auto-advances OFFERED->ACCEPTED->HELD synchronously in-process — no bus message, no deadline armed, no round. This is the "gate on collision-possibility" rule made literal; it is the SAME predicate T037 wants for "should I arm a listener."
2. SCOPE GATE (C2 vocabulary). scope is expressed as core/comm/locks.normalize_path() path-set and/or a task_ledger task id (lane-granular). An OFFER whose normalized scope intersects a live HELD token's scope is refused at offer time (offer-contention). Intersection is set-membership on normalized paths — the exact honest bound intent.py already lives with (fuzzy/semantic overlap deferred).
3. ROUND GATE (bounded negotiation). COUNTERED legal only if round < N (N=2). A COUNTER must narrow at least one negotiable field (scope subset via locks.normalize_path set-subset, or estimate) — an EMPTY-COUNTER (no field change) is rejected as a no-op. Rounds exhausted -> DECLINED with a durable negotiation_dead event.
4. ACCEPT / STALE-ACCEPTER FENCING GATE (RB-21 generations). An ACCEPT carries the offer's round + idempotency_key; it is refused if the offer has since moved (newer counter round, or already accepted). On the winning ACCEPT->HELD, the holder claims the lease via runner_lock.acquire(agent=SCOPE_KEY, token=holder_token) — KEYED ON THE SLICE, NOT THE AGENT (the crucial inversion of RB-21, whose seat is agent-keyed and therefore collapsed under twins). acquire() mints a fencing generation (GEN_PREFIX INCR) recorded in the token's generation field. A second, stale accepter loses the nx SET and, holding a different holder_token, is refused — and any late cursor/state write it attempts is fenced by the guarded generation check (bus.advance_to's _ADVANCE_LUA STALE_GENERATION path, the identical mechanism). Exactly one HELD per scope, structurally.
5. HELD LIVENESS + PROGRESS GATE. HELD liveness IS a runner_lock lease: refresh() calls runner_lock.heartbeat(SCOPE_KEY, holder_token) each turn/loop and REQUIRES a non-empty prog

## DESIGN T037

MECHANISM: PROBLEM (mechanism confirmed from source, not the note alone). The ceremony loop is powered by two seams acting together:

1. scripts/hooks/claude_stop.py:main (~line 203) blocks the stop whenever `wake_armed(session_id)` is False. wake_armed reads the PER-SESSION seat file (_seat_path -> bifrost_wake_<agent>_<sid>.pid) and demands THIS session have its own live listener. It knows nothing about sibling sessions of the same agent id.

2. core/comm/bifrost_api.py:wake_block (~line 109-113) SEEDS its local detection cursor `_wake_since` from `self.bus.cursor()` (the SHARED agent-id cursor) whenever that cursor is non-virgin. bus.wait(since=..., since_out=...) then does an xread starting AT that position; if unread mail already sits past the shared cursor, xread returns it IMMEDIATELY (block only waits when nothing is past the id). For a REAL consumer this is correct (it should wake to drain its backlog). For a NON-HOLDER co-tenant that can never advance the shared cursor (consume_inbox degrades to peek — agent/bifrost_pull.py:consume_inbox / bifrost_api.inbox), the shared cursor stays permanently behind tail, so every re-armed watcher re-seeds at the stale shared cursor and insta-returns the same backlog -> fires -> exits 0 -> harness re-invokes -> stop hook demands a listener again -> goto arm. 20-40 cycles observed live (note t037-firsthand-wakeloop-data, id ADR_0712031218_ac8fde81).

The fix has two reinforcing parts. Part 1 is the loop-breaker; Part 2 is defense-in-depth for the residual fallback path.

PART 1 — Stop-hook wakeable-by-proxy (the loop-breaker). Insert a `_proxy_wakeable(session_id)` gate in claude_stop.py:main BETWEEN the `wake_armed` failure and the block (currently line 203). New control flow:
  if wake_armed(my_session):            # unchanged: I have my own listener
      pass
  elif _proxy_wakeable(my_session):     # NEW: a live sibling that consumes is already armed
      pass                              # wakeable-by-proxy -> stop cleanly, arm NOTHING
  else:
      <existing block: arm your own listener>   # unchanged safe fallback

_proxy_wakeable(my_session) (pure-ish, fail-CLOSED to the safe fallback on any error):
  a. holder = runner_lock.holder(AGENT)  (core/comm/runner_lock.py:holder). If None -> return False (no consumer seat exists; I may be the intended consumer -> arm).
  b. my_token = f"session:{my_session}" (matches the token the hook already refreshes at line 201 and runner_lock.session_holder_token()). If holder.get("token") == my_token -> return False (I hold the consumer seat -> I AM the consumer -> I must arm my own listener; never defer the consumer).
  c. holder_session = holder["token"].split("session:",1)[1]. Enumerate wake_seat.iter_seats(AGENT) (core/comm/wake_seat.py:iter_seats) and find a seat whose session_id == holder_session with a LIVE pid (reuse claude_stop._pid_alive on wake_seat.read_pid(path)). If found -> return True (the live seat-holder — a real Claude session with its own stop hook and listener — is armed; the agent id is wakeable AND the waker is the one that consumes). Else -> return False (holder has no live listener; fall back to arming so the agent id never goes dark).
This ends the loop because a genuine non-holder now arms NOTHING and stops. It is exactly the note's direction (a)/(c). It degrades to CURRENT behavior (arm my own listener) whenever the proxy target is not provably a live armed consumer — so it can never make the agent id LESS wakeable than today.
