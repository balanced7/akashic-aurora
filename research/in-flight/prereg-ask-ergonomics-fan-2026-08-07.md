# PRE-REG: point the fan at its own door -- ask-verb ergonomics

Status: current (2026-08-07)
Committed BEFORE the fan runs. Daniil's ask: "use the fanouts we've built, improve the
ergonomics of the system, and refine the ask verb so it becomes an even better tool for this."

## Why this shape

The fan (`ask --prompts-file`, T181) is the instrument. The `ask` verb is its own door. So this
is `an_instruments_blind_spot_sits_where_it_is_looking` run deliberately: every new detector gets
pointed at itself before it gets pointed at the corpus.

The helpers have NO TOOLS -- they read what `--with` inlines and nothing else. Therefore every
branch returns a HYPOTHESIS, never a finding. Ratification is mine, by RUNNING the command.
That is the house law (`instrument_proposes_never_self_ratifies`) and the standing lesson
`attack_your_own_scoring_rule_by_running_it_not_by_reading_it`, applied to a fan I am motivated
to report well of because I am about to publish its yield.

## The transect (5 branches, distinct lenses, one shared evidence pack)

Cross-cutting transect, not a breadth wavefront: one invariant per branch across the same door.

  B1 COLD ENCOUNTER  -- given only `--help`, what will a fresh caller get WRONG?
  B2 SILENT INERTNESS -- which accepted flag combinations do nothing, or something other than
                         what the flags say? (the T216 class: `--with` evaporated on the fan path)
  B3 UNACTIONABLE STATE -- which outcomes can this door produce that leave the caller with no
                         next move?
  B4 COST             -- what makes an ask expensive that need not be?
  B5 REACH            -- which capability is CLI-only, i.e. dead for a runner or an MCP seat?

## Predictions, on record

  P1  FALSE-POSITIVE RATE >= 50%. Of the distinct defects claimed across 5 branches, at least
      half will NOT reproduce when I run the command. Reading-level review of a 783-line module
      hallucinates behaviour; that is the expected base rate, not a disappointment.
  P2  DIVERSITY reads `distinct`. Five different lenses on one artifact should not collapse.
      If it reads `collapsed`, the lenses were cosmetic and the transect design is refuted.
  P3  >= 1 REPRODUCIBLE defect of the B2 class (accepted-but-inert). This is the class that has
      twice been found by playing rather than by review, so a fan that cannot find one is a fan
      that cannot see the class review already misses.
  P4  The MODAL claim will be `--help` ergonomics (B1), and it will have the WORST
      reproduce-rate of any branch, because help text is where a reader with no execution can
      most cheaply feel confident.

## Acceptance -- what makes this worth having run

  A1  >= 2 defects that reproduce by a command I can paste, each fixed RED-pin-first.
  A2  Every claimed defect is dispositioned in writing: REPRODUCED, REFUTED, or NOT-CHECKED.
      A refuted claim is kept, not deleted -- the false-positive rate IS the measurement of P1,
      and quietly dropping misses is how a fan gets a reputation it did not earn.
  A3  The per-branch yield is reported even where it is zero.

## Kill condition

If 0 defects reproduce, the honest report is that a tool-less fan cannot audit its own door, and
the recommendation is to stop spending on this pattern -- not to soften the bar until something
passes.

## Blind spot this pre-registration cannot close

I choose the five lenses, so the fan cannot find a defect in a dimension I failed to imagine.
A sixth "what did the other five miss" branch would be a completeness critic, and is deliberately
NOT in this round: it would let me score the transect's coverage using the same instrument whose
coverage is in question.
