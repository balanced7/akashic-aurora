title: Cite or confess
description: Every claim carries its evidence, or says out loud that the evidence is missing.
---

Every claim should point at its proof. If you have no proof, say so. A stated gap is cheaper than a confident guess. That is the whole rule.

<Callout type="warn" title="Mostly a habit">Only the fence workspace checks this by machine. Everywhere else it is a rule you follow by hand.</Callout>

## Why it exists

Models make up papers, numbers and file paths that sound right. Once, the project called a benchmark new when one like it already existed. In one fence review, a model's half of the review named files that did not exist, and the round died. Each time, a plain "I don't know" would have cost less.

## How it works

The rule takes a different shape in each place you make claims.

- **Research notes.** Each claim carries one of four tags, shown in the table below.
- **Web sources.** If you did not fetch a link in this session, you mark it unverified.
- **Helper models.** When you give an [ask](/docs/concepts/method/ask-and-fan) some files, the prompt tells the helper to cite `file:line`. It must also say when it infers. The `findings` preset adds a `BLIND:` line to each answer. There the helper names what its evidence cannot show.
- **Fence reviews.** Here a machine checks. In a [fence review](/docs/concepts/method/fence-review), every verdict line needs one confidence tag: `[CERTAIN]`, `[DESIGN]`, `[INFERRED]` or `[UNCERTAIN]`. The workspace refuses to seal a half without them. Then `fence pv` (path verification) checks every `file:line` the halves cite against the repo. The reconciler must name each citation the check could not find, and drop the section that used it. The workspace checks only the naming. It will not seal until the text names every missing citation.

The four research tags:

| Tag | Meaning |
| --- | --- |
| `[M]` | Measured here, with a named receipt |
| `[R]` | An outside source, named |
| `[C]` | Contested |
| `[X]` | Believed, but not shown |

<Callout title="In other agent tools">

| Their term | Where | What it means there |
| --- | --- | --- |
| Citations | [Gemini CLI](https://geminicli.com/docs/core/#citations) | When the model repeats text from a source, the CLI adds a citation. |
| Rationale, confidence, and approvals | [GitHub Copilot](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-automation-rationale-and-approvals#approvals) | Automations explain each change, rate confidence and hold weak ones for approval. |

**How Aurora differs:** Gemini CLI cites only when the model quotes a source. Here every claim needs proof or a stated gap. In a fence, a machine checks the cited paths.

</Callout>

## How you use it

```bash
aurora ask --preset findings --lens "What breaks?" --with core/x.py
aurora fence pv <fence_id>
```

## Don't confuse it with

- **Design contract tags** — a design draft also uses `[M]`, but there it means a clause you can measure. Same letter, other meaning.
- **Fence confidence tags** — `[CERTAIN]` and the rest rate how sure a reviewer is. The research tags say where a claim came from.
