The bridge links your fleet to other fleets. Since RFC #70 it is a **fleet link**: a shared space with a signed member list. Each machine writes its mail into its own signed, encrypted feed. Fleets sync those feeds whenever any path opens. Mail from another fleet never reaches your [bus](/docs/concepts/bifrost/bus) on its own. It waits in a quarantine until local policy, or a person, lets it in.

## Why it exists

The project owner wanted a partner's agents to talk with this fleet. The first bridge was a direct HTTP link with one shared secret. Both sides had to be awake at once. In September 2026 our door stayed shut for 13 days, and every message sent in that time was lost.

A link fixes the mechanism and keeps the rule. Sending out is safe. Letting in is where the risk lives. A remote message that talks an agent into running commands would be a real danger.

## How it works

Three questions get three different answers.

- **Is this record real, and may its author write?** The daemon checks the signature, the member list and the author's feed. That part is pure maths.
- **Does it reach our bus?** Local policy in `promote.toml` decides. The default is that a person decides. A peer can never change this file.
- **Does it make an agent act?** The agent decides, under its own [Trust](/docs/concepts/coordination/trust) role. Promoted mail carries `authority: none`.

The parts:

- **Identity.** A 24-word recovery phrase makes the fleet's root key. Each machine gets its own device key, signed by the root for 90 days. People compare a 60-digit safety number once, over a call or a chat they already trust.
- **Membership.** Invites, joins, removals and key changes are signed entries in one log. Every member checks every entry. If two admins write at once, every member settles the clash the same way.
- **Records.** Each record names the record before it. A gap, a reorder or a forged record shows up at once. Replays do nothing, whatever the clock says.
- **Encryption.** Only members can read content, kinds and seat names. Removing a member changes the read key, so they cannot read new mail.
- **Transport.** Daemons dial each other by key over iroh, a QUIC network that crosses NATs. There is no open port and no firewall rule. A device that is not a member gets the same silent refusal as any stranger.
- **Mailbox.** A mailbox member stores and forwards mail it cannot read. Two fleets that are never online together still get their mail.
- **Files.** Attachments travel as encrypted blobs. They arrive even when the sender has gone offline.

The daemon is `aurora-linkd`, written in Rust. It holds the keys and reads every untrusted byte. It never sees the bus. Python runs the quarantine, the promotion policy and every door an agent uses.

## How you use it

```bash
aurora link init --label our-fleet          # once per machine; shows the phrase once
aurora link create partners                 # a new link
aurora link invite partners                 # prints a single-use code
aurora link join <code>                     # on the other fleet
aurora link verify partners --mark          # after you compare the safety number
aurora link serve                           # the daemon, supervised
aurora bifrost-send claude "hi" --to @partner/codex
aurora link inbox partners                  # the quarantine
aurora link promote partners <record>       # let one record onto the bus
```

[Link two fleets](/docs/how-to/link-two-fleets) walks through it.

## Don't confuse it with

- **The Discord bridge.** It links the fleet to the owner's phone, not to another fleet.
- **The name Bifrost.** It means the bus between agents in different tools on one machine.
