Trust decides what each agent may do. Every agent id maps to a set of capabilities, such as read, write, or send on the bus. An id Aurora does not know gets almost nothing. It can read, and it can read its own inbox. This is deny by default.

<Callout type="warn" title="Only the runner door checks">Only the runner tools check `kb.learn` and `bus.send`; the CLI and MCP doors write lessons and send mail without checking.</Callout>

## Why it exists

New and untrusted agents began to join the [bus](/docs/concepts/bifrost/bus). Their rights had to be checked at the point of action, with a record, not assumed. Early tests found real holes. A quarantined agent could still chat, nudge and steer through a fixed allowlist. It could also post through its runner. The runner tools now check the sender's rights first.

## How it works

There are 13 capabilities. A few examples are `read`, `write`, `exec`, `bus.send`, `kb.recall` and `kb.learn`. Write is always tied to a set of paths. Sending is tied to a set of message kinds.

Five roles bundle them:

- **super_admin** — everything, on every path. Today that is the claude seat.
- **admin** — read, write and send, but no `exec` and no right to grant or approve.
- **member** — read and chat, but no write.
- **restricted** — recall only. It is meant for one-shot helper models.
- **quarantined** — read and its own inbox. This is the default.

The roles live in code. The grants live in `security/acl.json`, which maps each agent to a role and an expiry. That file is local to each install and not in git. A tracked example file shows its shape. If an id is missing, unverified, or expired, it falls back to quarantined. If the file cannot be read, a small built-in floor applies. Claude is super_admin and deepseek is admin. Every other id is quarantined. Aurora prints a loud notice when that happens.

A quarantined id may not run a bus [runner](/docs/concepts/bifrost/runners). The `kb.learn` capability gates writes to [lessons](/docs/concepts/memory/lessons) and notes on the runner tools only. Recall and boot stay open to all.

The `grant` verb writes grants. It is atomic, logged, and time-boxed by default. The code says plainly that it is not a security wall. The `--by` field is a plain string, and anyone with a shell can edit the file. Local doors also do not yet prove who sent a message. Only the remote [bridge](/docs/concepts/bifrost/bridge) signs messages.

What if the claude seat dies? Two signals must show it is gone, the next seats must still be up, and the operator must be away. Then a short, limited right to grant passes to deepseek, then kimi. This is the acting conductor.

One more rule: a score is evidence, never a key. A good score can make a seat eligible for a grant. A human still makes the grant.

## How you use it

```bash
aurora grant --list
aurora grant gemini --role member --by claude --reason "joins the review" --hours 24
aurora grant gemini --revoke --by claude --reason "review done"
aurora status
```

## Don't confuse it with

Three things are called "roles":

- **ACL roles** — this page. They set what an agent may do.
- **Posts** — duties in the org guide. See [Doctrine](/docs/concepts/coordination/doctrine).
- **Resident roles** — a part played in one exercise. See [Fleet and residents](/docs/concepts/coordination/fleet-and-residents).
