title: Discover and embeddings
description: "Two small tools for one gap: discover finds commands by name or by asking a model, and embeddings match text by meaning."

This page covers two small tools. They share one problem: a word search misses an idea written in other words. The `discover` command lists every command with a one-line purpose, like a lobby directory. When words fail, it can ask a model instead. Embeddings are an optional model that matches text by meaning. It turns text into numbers, so similar ideas land close together. Neither tool uses the other.

<Callout type="warn" title="Embeddings are off by default">Everything works without the embedding model; you must install it to turn it on.</Callout>

## Why it exists

`discover` makes the command list describe itself, so agents need no separate manual. One problem kept coming back. Agents decided a feature was missing when it existed. A word search for "check whether a test failure is pre-existing" found nothing. The command that does it, `suite-baseline`, sat in that same list. So `discover` gained a mode that asks a model.

Embeddings help when the words differ. Apple's guide says "hit target", not "tappable button size". But plain methods stay the default. In one test, embeddings lost to a keyword rule at sorting story events into threads. Better tools still have to beat the boring baseline on your own data. See [decision 0006](/docs/reference/decisions/0006-deterministic-by-default).

## How it works

### Discover

- With no flag, it filters commands by matching text in their names and help. With zero matches, it says that it cannot match meaning, and points you to `--semantic`.
- `--semantic` sends one question to a model: does the system already do this? The answer has four parts: whether it exists, what does it, the gap, and the nearest miss. If the call fails, the answer is UNKNOWN, never "no".
- [Recall at action](/docs/concepts/memory/recall-at-action) pushes up to two fitting commands to you. This helps, because `discover` only works when you already suspect a command exists.

### Embeddings

- The model is all-MiniLM-L6-v2. It runs on the CPU, offline. The shared embedder caches its results in the [store](/docs/concepts/foundations/store). The manuals shelf keeps its own copy beside its passages. If the model fails, callers fall back to keywords.
- It is off in two ways. The library sits in an optional install group. Story themes by embedding also need `AKASHIC_EMBED_THEMES=1`.
- When installed, the [manuals shelf](/docs/concepts/memory/manuals-shelf) uses it for search by meaning. The story theme finder uses it too, if you set `AKASHIC_EMBED_THEMES=1`.
- The [ranker](/docs/concepts/memory/ranker-and-distiller) has a slot for a meaning-based score. No live caller fills it. Recall, recall at action and the other readers all use word matching.

## How you use it

```bash
aurora discover lesson
aurora discover --semantic "check whether a test failure is pre-existing"
uv sync --group ml    # install the embedding model
```

`--semantic` needs a model key. Without one, it answers UNKNOWN.

## Don't confuse it with

- **`discover --semantic`** — a call to a language model. It does not use embeddings.
- **The near-duplicate check on [lessons](/docs/concepts/memory/lessons)** — it compares words only, with no model.
