Chronicles are the readable digests in the `chronicles/` folder. A program writes them from the raw records. You read them, but you never edit them. Think of a yearbook printed from the school records. To fix a mistake, you fix the record and print again.

<Callout type="warn" title="One file is stale">`chronicles/lessons.md` still holds six early lessons; nothing in the code writes it today.</Callout>

## Why it exists

People need a short, readable view of lessons, notes and the story so far. The raw stores are too big to read. The project settled on three [knowledge layers](/docs/concepts/foundations/knowledge-layers). Raw records come first, and no one rewrites them. The [store](/docs/concepts/foundations/store) keeps a summary of each, with a pointer back. Chronicles sit on top, and a program can always write them again. An early bug had two functions writing the same file, each wiping out the other. Now each file has one writer.

## How it works

The live writers share the [ranker and the distiller](/docs/concepts/memory/ranker-and-distiller). Each picks the top records and packs them into a budget. The notes digest also runs the faithfulness critic. Its file does not record the result. The story file skips that critic and prints a basic check for each chapter.

The main files are:

- **`memory.md`** — a digest of the live [notes](/docs/concepts/memory/notes-and-agent-memory). Every `note` write rebuilds it.
- **`story.md`** — the story of the work so far. The Chronicler on the [narrative spine](/docs/concepts/narrative/narrative-spine) writes it.
- **`lessons.md`** — meant to be a digest of the lessons. A function to write it exists, but nothing calls it. The file still lists six lessons from the first days, while the store now holds hundreds.
- **`adrs.json`, `failures.json`, `milestones.json`** — output from an old chronicle program that no longer exists. Nothing reads or writes them now.

The word "chronicle" belongs to this layer only. It never names the raw event log.

## How you use it

Read `chronicles/memory.md` for the state of the project. Read `chronicles/story.md` for how it got there. To rebuild `memory.md`, run `notes --project`. Never edit these files. Fix the records and let the program write them again.

## Don't confuse it with

- **The Chronicler** — the narrative process that writes `story.md`. It is one writer, not the layer.
- **The [ledger](/docs/concepts/foundations/ledger) and the event log** — raw records. They are never called chronicles.
- **The `chronicle` doc type** — a kind of document in the [library](/docs/concepts/memory/library). It has its own shelf there.
