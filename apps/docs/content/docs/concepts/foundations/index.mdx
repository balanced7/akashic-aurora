---
title: Foundations
description: "The ground floor of Aurora: where facts live, where events live, and the rules that keep both honest."
---

Every part of Aurora rests on two questions. What IS true right now? And what HAPPENED, in what order? The [Store](/docs/concepts/foundations/store) answers the first. The [Ledger](/docs/concepts/foundations/ledger) answers the second. Hold on to that split. The rest of the docs lean on it.

The project's name says the same thing. [Akasha and Aurora](/docs/concepts/foundations/akasha-and-aurora) are the record and the knowledge built on top of it.

Both parts save their data through [hybrid storage](/docs/concepts/foundations/hybrid-storage): files always, Redis when it is up. When a helper part breaks, the work goes on. That rule is [fail soft](/docs/concepts/foundations/fail-soft).

One rule governs history: the [append-only record](/docs/concepts/foundations/append-only-record). Nobody rewrites an event. A fix is a new record that retires the old one. The [knowledge layers](/docs/concepts/foundations/knowledge-layers) keep each fact at three depths. [Signals](/docs/concepts/foundations/signals) are the trails agents leave on the Ledger.

Three last pages cover order and words. The [layers](/docs/concepts/foundations/layers) stack the code in floors. [Relationship types](/docs/concepts/foundations/relationship-types) name the links between things. [Naming](/docs/concepts/foundations/naming) keeps every word honest.
