---
title: Decision records
description: The few decisions that shape Aurora and would surprise a newcomer, each with its reason.
---

A decision record says what we decided and why, in a few sentences. We keep one only when the decision is hard to undo, would surprise a reader and came from a real trade-off. Everything else lives in the code.

<Cards>
  <Card title="0001: Two storage primitives" href="/docs/reference/decisions/0001-two-storage-primitives" description="Everything persists through one of two shapes, chosen by asking whether you store what is or what happened." />
  <Card title="0002: Files are the durable copy" href="/docs/reference/decisions/0002-files-are-the-durable-copy" description="Aurora writes to files first and treats Redis as a speed-up that may be missing." />
  <Card title="0003: Never rewrite the record" href="/docs/reference/decisions/0003-never-rewrite-the-record" description="Corrections add a new record that replaces the old one; nobody edits or deletes history." />
  <Card title="0004: The bus is disposable" href="/docs/reference/decisions/0004-the-bus-is-disposable" description="Live agent mail rides a fast, throwaway bus, and only the messages that matter get copied into the durable record." />
  <Card title="0005: No file ownership" href="/docs/reference/decisions/0005-no-file-ownership" description="Any agent may edit any file, and live agents coordinate with short advisory locks instead of standing territories." />
  <Card title="0006: Deterministic by default" href="/docs/reference/decisions/0006-deterministic-by-default" description="Recall and routing use deterministic scoring, and a learned method becomes the default only after it beats that baseline on our own data." />
  <Card title="0007: Union, not consensus" href="/docs/reference/decisions/0007-union-not-consensus" description="When several models review the same work, we keep every finding and verify each one, instead of keeping only what they agree on." />
  <Card title="0008: Quarantine mail from another fleet" href="/docs/reference/decisions/0008-park-peer-mail" description="Messages from another fleet land in a quarantine and reach the live bus only by local policy; by default a person decides." />
  <Card title="0009: Charter means standing contract" href="/docs/reference/decisions/0009-charter-means-standing-contract" description="The word charter is reserved for a seat's standing contract, and one-off work orders are called briefs." />
  <Card title="0010: Generate status" href="/docs/reference/decisions/0010-generate-status-never-hand-write-it" description="Status and maps come from commands that read the live system, never from hand-kept documents." />
  <Card title="0011: Fleets sync through signed feeds" href="/docs/reference/decisions/0011-fleets-sync-through-signed-feeds" description="Fleets share a link with a signed member list, and a Rust daemon owns the keys while Python owns what agents touch." />
</Cards>
