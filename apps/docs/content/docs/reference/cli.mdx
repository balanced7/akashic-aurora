---
title: All commands
description: Every Aurora verb with its flags, generated from the CLI itself, and how each one prints for agents and for people.
---

This page lists every verb the `aurora` command offers. A script builds it from the CLI's own parser, so it always matches the code. For the verbs you will use most, start with [Commands](/docs/reference/commands).

Each verb prints for an agent or for a person. [Commands](/docs/reference/commands) explains how to choose with `--output agent` or `--output human`. A verb marked as converted has been measured before and after the change. The bench gives a reader model only the verb's output and checks its answers against known data.

121 verbs; 90 converted to agent and human output.

## `alias`

| | |
|---|---|
| Does | toolbelt authoring: mint/list/retire agent-authored verb compositions (sugar-only; honesty labels; quota) |
| Output | Agent mode (TOON) and human mode (colour). |

| Flag | Required | Values | What it does |
|---|---|---|---|
| `<agent_id>` | yes |   | whose toolbelt (the author) |
| `<action>` | yes | mint,list,retire,history |   |
| `<name>` |   |   | alias name (mint/retire/history) |
| `--step` |   |   | one step per flag, shell-style quoted; steps run in order (mint) |
| `--evidence` |   |   | VERIFIED\|INFER\|GUESS (default GUESS -- untested sugar confesses) |
| `--tested-against` |   |   | pin id proving this alias (upgrades evidence) |

| `--fields` |   |   | list: extra columns: kind,tested_against,why,updated_at, or 'all' (default: name,family,version,evidence,steps) |
| `--json` |   |   |   |

## `ask`

| | |
|---|---|
| Does | ask a helper model ONE question, synchronously (no seat, no lock, no mailbox -- it dies in the call) |
| Output | One format for every reader. Not converted to agent and human modes yet. |

| Flag | Required | Values | What it does |
|---|---|---|---|
| `<text>` | yes |   | the question (or use --prompt-file) |
| `--prompt-file` |   |   | read the question from PATH |
| `--system` |   |   | override the helper's system prompt |
| `--as-resident` |   |   | T261 tier-1: the branch answers AS a ratified resident -- its callsign, receipts and a catch-up pack of its OWN archive lessons ride the system context, and the reply is stamped tier=resident with the designation. NOT --as, which is the SENDER identity: one flag carrying both meanings is the T174 homonym class. A non-resident refuses BEFORE any model call. |
| `--model` |   |   | override the helper model |
| `--max-tokens` |   |   | answer ceiling; hitting it returns a marked PARTIAL, never a silent cut |
| `--fan` |   |   | ask the SAME question N times concurrently: N samples of ONE model on ONE prompt, so agreement is self-consistency and NOT independent verification -- correlated samples fail together. For decorrelated evidence vary the POSITION with --prompts-file. STATELESS only: cannot be combined with --peer, one durable ask to one seat |
| `--prompts-file` |   |   | T181: run MANY questions at once. JSON array, or prompts separated by a line containing only --- (so a prompt may be multi-line) |
| `--geometry` |   |   | T281: declare the fan's SHAPE so the route journal can score routes. WHEN TO FAN: wide independent reading -&gt; fan; deep sequential reasoning -&gt; one seat; verification -&gt; diverse lenses; corpus-level claims -&gt; add a backbrief. Shapes: partition (shards over a corpus -- coverage), lens (same pack, different questions), panel (--fan N self-consistency, never verification), adversarial (position + refuters), backbrief (non-author raw-access re-check), wave (repeat until dry), negotiation (shared-artifact construction only). Wrong combinations are refused with the expected shape. |
| `--preset` |   |   | named answer contract, e.g. 'findings' (FINDINGS/REASONING/CHECK/BLIND). Supplies the contract to every branch AND parses the answers back, so --json returns structured results. Use with --lens/--lens-file. |
| `--lens` |   |   | one branch per --lens, each with the preset's contract appended. Repeatable. The lens leads, the contract follows. |
| `--lens-file` |   |   | one lens per line; blanks and # comments skipped, so a lens file can record WHY each lens is there -- the part that rots first. |
| `--workers` |   |   | fan width (default 6). Merge attention binds before generation does -- a fan wider than its integrator makes debt, not progress |
| `--peer` |   |   | T196c: ONE durable ask to a SEAT (send+arm+poll on the bus) instead of the stateless helper. The expectation outlives --wait; timeout hands back a --status handle. ONE seat, ONE ask: cannot be combined with --fan/--prompts-file |
| `--wait` |   |   | interactive patience in seconds for --peer (default 120); the DURABLE expectation keeps redriving after it |
| `--poll` |   |   | poll interval for --peer (default 2s) |
| `--bg` |   |   | run this ask in a DETACHED child and return a handle immediately -- the answer waits in a file instead of your context. Fan out without drowning |
| `--get` |   |   | read a background ask: RUNNING / DONE / FAILED / ORPHANED, each with what to do now. A READ, so it cannot be combined with --bg (which is a spawn) -- passing both is refused rather than silently picking one |
| `--list` |   |   | recent background asks, newest first |
| `--bg-child` |   |   | ==SUPPRESS== |
| `--no-continue` |   |   | do NOT resume a CUT answer. Continuation is ON by default: with no token ceiling, a cut means the model hit its OWN limit, and stitching costs one completion while a re-ask pays for the whole prompt again. Never fires for a STARVED answer -- there is nothing to continue |
| `--continuations` |   |   | how many continuations --continue may spend (default 2); running out still reports PARTIALLY, never a clean done |
| `--with` |   |   | inline a repo file into the ask, WITH LINE NUMBERS, so the helper can cite file:line instead of reasoning blind. Repeatable; one shared char budget; truncation and unreadable paths are stated, never silently dropped |
| `--launch` |   |   | with --peer: if nobody is home, LAUNCH the seat first, wait for it to attend, then ask. The launcher's singleton gate is the only single-flight; an ambiguous peer is never guessed |
| `--launch-wait` |   |   | how long to wait for a launched seat to attend (default 60); readiness is a liveness probe, never a sleep |
| `--status` |   |   | T196d: render one durable ask's honest state (seven states incl UNKNOWN) and what to do now. Read-only; always exit 0 |
| `--as` |   |   | the SENDER seat the ask belongs to (expectations are per-sender; default $AKASHIC_AGENT_ID or claude) |
| `--json` |   |   |   |
