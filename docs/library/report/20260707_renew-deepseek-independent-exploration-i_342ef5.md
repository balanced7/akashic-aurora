## 1. How This Folds Into the Membrane Design

The membrane has four named jobs:

| Job | What it does | Where it lives |
|-----|-------------|----------------|
| **Surface** | Inject the right context at the moment of action | `core/recall/at_action.py` (PreToolUse hook), `context/aggregator.py` (boot) |
| **Capture** | Auto-log what's salient | `core/narrative/session.py` (session lifecycle), outcome-credit auto-emit |
| **Enforce** | Auto-adherence to what matters | `scripts/check_boundaries.py`, `check_doc_freshness.py`, `check_door_parity.py`, `check_wiring.py` |
| **Unify** | One coherent door | `agent_cli.py` (33 verbs), `ai_setup_mcp.py` (22 verbs), bus API (18 verbs) |

The proposed context lifecycle management — estimate "context health," detect cognitive debt, do a curated SAVE + RELAUNCH — is **a fifth job** that stitches Surface and Capture into a closed loop *across the session boundary*. The membrane doc already names it **Renew**: "keep working context healthy over long-running work: detect cognitive debt → extract durable knowledge (*Capture*) → reload a curated working set (*Surface*)."

**My read: it is NOT a new subsystem.** It is a **control loop over already-built primitives**: `snapshot` (save) + `boot` (reload) + `distiller` (extract durable) + `launcher` (respawn) + `supersession` (retire stale) + `funnel` (measure if it helped). The only genuinely new primitive is the **context-health estimator** — a deterministic scorer that reads signals already being logged.

The membrane itself was the same story: half-built as the hook layer, named and finished. Renew is the same shape: the pieces exist, the missing piece is the **detector + policy** that triggers the loop.

## 3. Prior Art and How We Differ

### 3.1 MemGPT / Letta (arXiv 2310.08560 — Packer et al., 2023) — HIGH CONFIDENCE

MemGPT treats LLM context as virtual memory: an OS-paging model over Main context (in-context window) and External context (recall + archival storage). The agent has a fixed-size main context and pages data in/out. This is the closest prior art to the four-tier proposal.

**Our delta:** MemGPT uses an **LLM as the paging controller** (the agent decides what to page). Our design rejects that — the paging function is **deterministic** (health signals, not another LLM call). MemGPT pages at a **fixed token threshold**; we trigger on **quality signals** (duplication, superseded density, file-reread rate). And critically, MemGPT pages *summaries* — we page *lossy summary + lossless source pointer*, so the raw record is always recoverable. Our Ledger *is* the event log, not a derived summary blob.

### 3.2 Anthropic's Agentic Context Guidance — HIGH CONFIDENCE

Anthropic's published guidance (referenced in `docs/context-compaction-skeleton-research.md`) states: the **harness owns context management**, compaction at a token threshold is standard, and the harness queries event-stream slices to rebuild context per model generation. Our Context pillar *is* that harness. Anthropic's approach already uses **LLM compaction at a token threshold**.

**Our delta (four axes):**
1. **Trigger:** Deterministic health/lifecycle signals, not raw token count
2. **Extraction:** NO-LLM distiller over event-based records, not lossy LLM summary
3. **Scope:** Durable cross-session continuity, not ephemeral compaction within one conversation
4. **Warrant:** Gated by benchmark evidence (`coord/experiment.py`), not assumed beneficial

### 3.3 Chroma "Context Rot" Research — MEDIUM CONFIDENCE

The finding that context size ≠ context quality — that 30%+ of information is "lost in the middle" of long contexts across 18 models — is empirically well-established. This forces the conclusion that a quality-based trigger (not size-based) is necessary.

### 3.4 Blackboard Systems / Terrarium / LbMAS — HIGH CONFIDENCE

The field has independently converged on blackboard-mediated agent coordination (Terrarium: arxiv 2510.14312; LbMAS: 2507.01701). The key finding relevant here: **"agents neither message directly nor keep private histories"** — context is pulled from shared state, not carried. This validates our architecture where the Ledger/Store is the shared medium and agents boot from it rather than carrying forward chat transcripts.

### 3.5 Sleep-Time Compute — MEDIUM CONFIDENCE

The idea of doing compute at context boundaries (save/compress at session end, prepare at session start) to reduce in-session token burn by ~2.5–5× appears in the literature. This directly supports the Renew loop: extract durable knowledge at the boundary, reload curated context on boot.

### 3.6 What I did NOT find (honest gaps)

I found **no prior system that combines deterministic health estimation + event-driven refresh + lossless-pointer compaction + agent-type-matched enforcement fidelity in a single control loop**. The pieces exist separately; the integration is novel.

## 4. What Is Genuinely NEW and What Research Is Needed First

### 4.1 The one genuinely new primitive: Context-Health Estimator

Everything else in the proposal is wiring over existing primitives. The **context-health estimator** is the single genuinely new module. It must score a single agent's live working-context quality from deterministic signals.

**Candidate signals already being logged** (from `cognitive_metrics.py` and other modules):

| Signal | Where it's already captured | How it indicates debt |
|--------|---------------------------|----------------------|
| **File-reread rate** | `cognitive_metrics.py` `record_file_read()` tracks duplicate reads | High = agent forgot what it already read |
| **Tool-call repetition/backtrack rate** | `cognitive_metrics.py` `record_tool_call()` classifies each call | Re-reading the same files, re-running the same commands |
| **Turns-since-boot** | `cognitive_metrics.py` `duration_s` | Long sessions accumulate cruft |
| **Task-ledger churn** | `task_ledger.py` transition history | Frequent BLOCKED/ABANDONED = confused agent |
| **Superseded-record density** | `supersession.py` edges in live context vs. project state | High density = agent is operating on stale plans |
| **Stale-lock count** | `locks.py` advisory locks | Abandoned locks = confused coordination |
| **Coordination token ratio** | `cognitive_metrics.py` `coordination_token_ratio` | High = agent is fighting the environment, not working |
| **Recall value rate** | `funnel.py` `value_rate` | Low = surfaced knowledge isn't helping |

**Design constraint** (from the faithfulness principle): the estimator must be **deterministic**, not an LLM judge. This is non-negotiable — it's the same principle that produced the `faithfulness.py` critic.

### 4.2 Research needed FIRST (in priority order)

**A. [EMPIRICAL — MUST COME FIRST] Cheap deterministic health signals that predict degraded output.**

This is the gating item. Before any refresh policy exists, we need to know whether the signals actually correlate with worse outcomes. Method: instrument the signals above → correlate against outcome signals we already have (FAIL→SUCCESS flips in `at_action.py`, funnel helped-rate, task completion rate, `cognitive_metrics.py` waste_ratio). Without this correlation, the health estimator is guessing.

**Why this is load-bearing:** Anthropic's own harnesses already do LLM compaction at a token threshold. If we're going to build something different (quality-based trigger), we need evidence that quality-based is *better* than size-based, not just different.

**B. [DESIGN] Refresh-decision policy.** Map health signals + lifecycle events onto the fidelity ladder:
- **Interactive agent** (Claude Code, Cursor): INFORM/STEER recommendation through the membrane — never force-relaunch a human-in-loop session
- **Stateless runner** (deepseek runner, gemini bridge): HALT + respawn is enforceable
- **Hybrid** (headless Claude): depends on the harness

The fidelity ladder already exists (`interject.py` HALT/STEER/ASK, `nudge.py`, `control.py` PAUSE/HALT). The new work is mapping health scores to action recommendations.

**C. [EMPIRICAL — THE GATE] Does refresh actually help?** A/B test via `coord/experiment.py` + `cognitive_metrics.py`: refresh-on-debt vs. run-long. Metric: rework rate, output quality, tokens consumed. This is the benchmark that gates whether Renew ships — per the project principle that every slice is gated by evidence.

**D. [EMPIRICAL] Cold-resume fidelity.** Is the existing curated save (boot payload from `context/aggregator.py`) *sufficient* to resume as well as full context? Test directly. If yes, Renew is mostly wiring; if no, the distiller needs improvement before any of this matters.

### 4.3 What is NOT needed (already built)

- **A new save mechanism** — `snapshot.py` + `consolidation.py` + `distiller.py` already handle curated extraction
- **A new relaunch mechanism** — `launcher.py` already handles spawn/kill/revive with backoff
- **A new context assembly** — `context/aggregator.py` already assembles ranked, budget-fitted boot context
- **A new wedge detector** — `liveness.py` already detects stuck agents
- **A new lifecycle event system** — `task_ledger.py` + `conductor.py` already emit task transitions
- **A new evidence harness** — `coord/experiment.py` + `coord/metrics.py` already provide A/B infrastructure
- **A new faithfulness gate** — `faithfulness.py` already grounds extractions against sources
- **A new fidelity mechanism** — `interject.py` + `control.py` + `nudge.py` already provide the action ladder

### 4.4 Design anti-patterns to avoid (baked into the existing architecture)

1. **Never raw token count as the trigger.** Health ≠ usage — a 48%-full context thick with superseded plans is worse than a 72%-full coherent one. The existing `cognitive_metrics.py` already tracks richer signals.
2. **No LLM judge for health.** Violates the NO-LLM faithfulness principle AND token-frugality. Start deterministic — the same discipline that produced `faithfulness.py`.
3. **Evidence-gate it.** No policy ships without a benchmark that it improves outcomes. The `coord/experiment.py` harness exists for exactly this.
4. **Metric before dashboard.** A cognition dashboard is the payoff, but observing a metric that does not yet exist is theater.

## 5. Synthesis: Renew as the Membrane's Fifth Job

The four existing membrane jobs operate **within** a live session. Renew operates **across** the session boundary — it is **Capture → Surface fired as a loop**:

```
agent works ──→ cognitive debt accumulates ──→ health estimator fires
    ↑                                               │
    │                                               ▼
    └──── boot (Surface) ◄── curated save ◄── extract durable (Capture)
```

The pieces that exist:
- **Capture:** `distiller.py` + `consolidator.py` + `consolidation.py` + `faithfulness.py` = extract durable knowledge from the working set with lossless source pointers
- **Surface:** `context/aggregator.py` + `ranker.py` + `distiller.py` = assemble a curated, budget-fitted working set
- **Detect:** `cognitive_metrics.py` + `liveness.py` + `funnel.py` = observe signals; but **no health estimator exists yet**
- **Enforce:** `launcher.py` + `control.py` + `interject.py` + `nudge.py` = stop/restart/recommend with fidelity-matched actions
- **Gate:** `experiment.py` + `metrics.py` = A/B test whether it works

**Net assessment:** The proposal is ~60% built already — same story as the membrane itself was. The one new primitive (health estimator) is small and deterministic. The wiring (policy + fidelity mapping) is modest. The gating item is empirical: do the health signals actually predict degraded outcomes? Answer that first, then build.
