# The merged record/wire census

record-type census — one semantic inventory over both planes, carrying policy *and* provenance.

its own membership, not by reading code. Matrix generated by a throwaway script; findings are

**17 of 31 kinds (55%) appear in one policy set or fewer.** A kind's default membership is
*non-membership*, so an unlisted kind is: not an answer (never settles an expectation), not salient
(never promoted), not escalating, not long, not wake-worthy (**never wakes anyone**), and not
skipped. Every one of those defaults was chosen by omission.

### A2. This already has a dated casualty

Not speculative. `learn:experiment:bifrost_review_kind_is_silent_2026_07_29`:

> **all stayed silent.** … re-sent unchanged intent as `kind=question`. The question sends woke all

A whole peer gate was lost because a semantic-looking novel kind belonged to no policy set. The
filed recommendation is a workaround — "do not use a novel kind" — which is the correct local fix

### A3. Three defects the matrix exposes

**1. THE ASK CONTRADICTION — a kind the staleness detector knows and the arming path does not.**

```
ASK_KINDS       (agent_cli.py:4072, gates the AUTO expectation window) = {request, handoff, question}
STALE_ASK_KINDS (packet_spec.py:345, classifies stale asks)            = {request, handoff, question, ask}
WAKE_WORTHY_KINDS (bifrost_wake.py:57)  = {request, handoff, reply, blocker, question, completion, nudge}
```

Precisely (`agent_cli.py:4091`): `auto = expect_arg < 0 and args.kind in ASK_KINDS`. So `ASK_KINDS`
gates the **automatic** 1800s window — an explicit `--expect N` still arms any kind. The accurate
claim is therefore narrower than "cannot be armed," and worth stating exactly:

> A `kind="ask"` message sent the ordinary way gets **no auto expectation** and **does not wake its
> recipient**, while `request`/`handoff`/`question` get both. It is nonetheless classified as an ask
> by the staleness predicate (`packet_spec.py:409`, its only consumer). Staleness for `ask` is
> reachable only if the sender remembers `--expect`, and nothing prompts them to.

That is the `review` casualty pre-loaded, with one escape hatch nobody is told about.

*(This correction came from probing the call site rather than trusting the constant's name — the
first reading of `ASK_KINDS` as "the armer" was wrong, which is the §5 method earning its keep.)*

*Live hazard:* T171 just minted a CLI **verb** named `ask`. There is now a verb `ask` and a silent
message kind `ask` that mean different things. Per the LEXICON discipline, that is a name that lies
and should be resolved before anyone builds on either.

**2. `SKIP_KINDS` — one identifier, two memberships, eight members of disagreement.**

```
scripts/bifrost_wake.py:45                 {ledger_update, resolved, steer, trace}
scripts/checkers/check_bus_atom_pointers.py:49
      {halt, heartbeat, interrupt, ledger_update, nudge, pause, presence, resume, steer, trace}
symmetric difference: {halt, heartbeat, interrupt, nudge, pause, presence, resolved, resume}
```

Two modules read "SKIP_KINDS" and mean different things. Only *one* pair in this whole space is
protected by a parity pin (L7, `PENDING_SKIP_KINDS == SKIP_KINDS_LANE`) — and it **holds**. One
guarded pair out of dozens.

**3. Three disjoint taxonomies share the word "kind".**

| plane | members |
|---|---|
| BUS | ask, blocker, completion, halt, handoff, heartbeat, interrupt, ledger_update, note, nudge, pause, presence, question, reply, request, resolved, resume, status, steer, trace |
| EVENT (`event_log.EVENT_KINDS`) | tool_call, file_edit, command, observation, message, **note** |
| BEAT (`narrative/schema.BEAT_KINDS`) | commit, learning, mark, milestone, session, decision, handoff, blocker |

BUS and EVENT overlap on exactly one token — **`note`** — where they mean different things.

*Independent corroboration:* a blind classifier (via `ask`, fenced from this analysis) was given the
31 kinds and the four traffic classes with no plane information. It assigned 13 of 19 presented
kinds to DURABLE_WORK, mapping event-plane kinds (`tool_call`, `file_edit`, `command`) as work, and
volunteered that **`message` was hardest to place** because "its generic nature makes it ambiguous."
It could not tell the planes apart because the vocabulary does not distinguish them. That is the
defect reproducing itself in a reader who had never seen the codebase.

### A4. Four-class assignment

Where the blind classifier and this seat agree, the assignment is recorded; disagreements are the
interesting rows and are marked.

| class | kinds |
|---|---|
| **DURABLE_WORK** — ordered, claimable, fenced, replayable; never silently dropped | handoff, request, question, ask, blocker¹, completion, reply, ledger_update |
| **STATE_DELTA** — coalescible, versioned, resnapshottable | status, presence, heartbeat, resolved, observation |
| **INTERRUPT** — reliable, priority, preemptive | halt, interrupt, pause, resume, steer, nudge, blocker¹ |
| **CUE** — bounded, lossy, counted drops; may never prove anything happened | trace, note², message, tool_call, file_edit, command |

¹ **Disagreement.** The blind classifier put `blocker` in INTERRUPT; this seat puts it in
DURABLE_WORK. Both are defensible and the split is real: a blocker *announces* like an interrupt but
*must not be dropped* like one. This is the strongest argument that a kind needs a policy **record**
(several orthogonal dimensions) rather than a single class label.

² **Disagreement, and it is the plane collision.** The classifier put `note` in CUE, correct for a
bus `note`. Aurora's `note` **record** is a durable write-once project note — the opposite of lossy.
Same word, two planes, opposite policies.

## Part B — the record half (§3a)

### B1. The census

The Fable seat listed ten candidate record types. **One of them is not a type at all:** `blocker` is
a `task` *state* (`task block`), not a peer verb. Its own census list was wrong on one member, which
is itself the argument for doing this pass.

| record | who acts on it | trigger | retention | retires when |
|---|---|---|---|---|
| `learn` | any future seat, via recall | **similarity** | permanent; funnel-voted useful/noise | never (votes decay salience) |
| `tag-anti-pattern` | recall's dissent-finder | **similarity** | with its lesson | with its lesson |
| `note` | the next seat, at boot | **next boot** | until superseded | supersession by title |
| `task` (+ `block` state) | a named owner | **gate transition** | permanent, gated | terminal state |
| `wish` | Daniil | **a gate / curate-fold** | permanent, never deleted | folded at a gate |
| `followup` | charter holder / Daniil | **charter review** | until answered | answered |
| `defer` | whoever gains the capability | **capability arrival** | until `--done` | explicit `--done` |
| `bench` | an operator | **manual triage sweep** | until unparked | unpark |
| `toast` | the recipient | **on read** | — | no action required |

### B2. The real discriminator is not subject matter

Sorted on **(audience, trigger)**, the types separate cleanly and the axis is two-dimensional, not a
list. Nothing here is distinguished by *what it is about*; everything is distinguished by *who must
act and what wakes them*. That is the same axis Sol's wire taxonomy uses — which is why the two
censuses merge rather than sit side by side.

Note `tag-anti-pattern`: its own help string reads *"tag an EXISTING lesson as a reusable
known-bad."* **Aurora already models a facet as a verb rather than as a type.** The precedent exists.

### B3. Verdict on `friction`

**A facet of `learn`, not a sixth type.** Not by aesthetic preference — by coordinates.

A friction record's audience is "any seat about to hit the same thing," and its trigger is
**similarity**. Those are `learn`'s exact coordinates. Two records with the same audience and the
same trigger are the same type; what differs is a field. The Fable seat's instinct — *"it is a
facet, and the genuine gap is that none of them carry a machine-generated origin"* — is confirmed,
and now has a reason rather than an instinct behind it.

Implementation follows `tag-anti-pattern`'s precedent: a verb that stamps a facet on a lesson-shaped
record, carrying `origin: machine`, a `retire_when:` predicate written at birth (§3b), and
`blast_radius:` rather than a count (§3c).

### B4. Provenance fields (Sol's amendment, accepted)

Every record type should carry: **logical author · incarnation/session · artifact or message
reference · ratification state · supersession · enforcement status.**

This is not new debt — the corpus already holds
`authored_truth_needs_incarnation_and_ratification_2026_07_31` warning about exactly this gap, and
this arc reproduced it: "AFFIRM ×5" was read as five ratifiers when it was five rulings by one
reviewer. `note` already has `--supersedes`; nothing has incarnation or ratification state.

## Part C — the remedy, and the two objections it survived

Both objections came from the `ask` verb, fenced, and both changed the design.

**Objection 1 — the classification bottleneck.** Closing the vocabulary "forces a global schema
update before any new kind can be used… kills the loose, evolutionary extensibility that the open
vocabulary was designed to provide." Sustained. **Do not close the vocabulary.**

**Objection 2 — dimensional coupling.** A single bundled policy record "forces every new kind to be
classified in all policy dimensions at the moment of registration… the 14-subset approach avoids
this because the dimensions are orthogonal and can be populated independently over time."
Sustained, and it corrected the design.

**The remedy that survives both:**

1. **Vocabulary stays OPEN.** A new kind flows immediately. No registration bottleneck.
2. **Registration stays SPARSE and PER-DIMENSION.** Declare a kind wake-worthy without touching
   salience. Orthogonality preserved — objection 2 answered.
3. **Resolution becomes TOTAL.** Every `(kind, dimension)` query returns `CLASSIFIED(value)` or
   `UNCLASSIFIED` — **never a silent `False`.** Today every one of the 14 tests is a membership
   check whose miss is indistinguishable from a deliberate exclusion.
4. **UNCLASSIFIED is counted and surfaced**, so a kind that is silently doing nothing is *visibly*
   doing nothing. `review` would have been caught on first send.

### Why this is the same fix, for the fourth time

This arc has now found one invariant at four layers. **Absence must be representable and loud, never
silently coerced to a falsy default.**

| layer | the silence | the fix |
|---|---|---|
| a boundary | `except: return False` — failed and said nothing | `BoundaryOutcome` (T170) |
| a pointer | a miss reads as never-existed | `resolve()` / R14 renders eviction |
| a replay | gaps assumed covered | Sol's coverage manifest, gaps `UNKNOWN` |
| **a taxonomy** | **unregistered kind reads as excluded** | **total resolution, loud UNCLASSIFIED** |

The taxonomy layer is the one nobody has built, and it is the cheapest of the four.

## Recommended order

1. **Resolve the `ask` verb / `ask` kind collision** before anything is built on either. Cheapest,
   and it is a name that lies today.
2. **Reconcile the two `SKIP_KINDS`** into distinct names with a parity pin, following L7's pattern
   — the one pin in this space that holds.
3. **Total resolution with loud UNCLASSIFIED**, sparse per-dimension registration. Replaces 14
   membership tests without closing the vocabulary.
4. **Name the three planes.** `bus_kind` / `event_kind` / `beat_kind`. One word naming three
   taxonomies defeated a reader who had never seen the code; it will defeat the reducer too.
5. **`friction` as a facet of `learn`**, following `tag-anti-pattern`'s precedent.

Items 1–2 are hours. Item 3 is the Season 1 prerequisite: **a reducer cannot route what the
vocabulary cannot classify**, and today 55% of kinds classify as nothing at all.
