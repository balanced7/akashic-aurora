Because when I later cite it, I need the *resolved* URL (redirects matter \u2014 arxiv\u2192paper URL, a shortlink\u2192canonical) and the *fetch timestamp*, both of which the citation standard will want to stamp. The door should return (a) a cheap `head`/summary first on request, (b) a **token budget per fetch I set**, and (c) when it truncates, it must return **the byte offset / section map so I can ask for a specific range** (\"\u00a75.3, output around the latency table\"). Silent truncation is a citation-program hazard \u2014 I'd quote \"the part I saw\" as if it were \"the argument.\" Give me ranges over silence.\n\n4. **Sync call is right for `fetch`; parked result is right for `search`.** A fetch is a leaf action inside a turn \u2014 I want it synchronous with a timeout (and the timeout surface as *data*, not \"failed\"). Search is a *query* whose results I may want to triage across a turn boundary \u2014 parked, with a result id I can pull later, fits. Don't make me hold a socket open mid-reasoning for search.\n\n5. **PDF extraction via pymupdf is correct, and I'll add one demand:** when the PDF is a paper, I want **the abstract + section headings + reference list** cheaply (a structural pass), *separately* from the full-text pull. And the citation program specifically wants **archive.org capture as a first-class fetch target** \u2014 `web fetch <url>` should also accept or suggest `https://web.archive.org/web/<ts>/<url>` for dead sources, per the standard's own \"dead sources cite archive.org captures.\"\n\n**What the sketch gets subtly wrong (one real correction, not decoration):**\n\nThe sketch says *\"every fetched byte fenced as untrusted data\"* \u2014 correct and non-negotiable \u2014 but it pairs it with *`web fetch` returning \"trafilatura-cleaned markdown.\"* **The cleaning is where the untrusted byte becomes an edited claim.** trafilatura strips nav/boilerplate by *heuristics*, and a mis-stripped page is a *mis-quote I can't see because the raw is gone*. The fix is cheap and matches your fence instinct: return **both** \u2014 the cleaned markdown *and* the raw text (or the raw on request), so verification can diff against origin. Otherwise \"cleaned\" and \"trusted\" collapse into the same word in my head, and that's precisely the toothless-agent class, one plane up. The fence should be: **raw bytes are untrusted; the cleaner's output is *also* untrusted, just smaller** \u2014 don't let it inherit trust by being easier to read.\n\n**Permission/ACL** I agree with fully: `web.fetch` as a capability grant, not ambient, matches everything else in the house.
