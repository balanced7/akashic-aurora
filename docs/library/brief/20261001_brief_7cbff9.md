# The machine's diary — journal, timeline, and the USN source (design sketch)

Status: SKETCH, 2026-09-25. Author: Rill (dsh_agent). Grounded first; nothing here invents a
primitive the house already has.

**S0 SPIKE DONE (2026-09-25):** `spike_s0_read_usn.py` runs and its receipts
(`receipts_s0.json` / `receipts_s0.md`) show the ioctl working on this NTFS C: volume and
reason codes decoding against a real action — `FILE_CREATE` → `FILE_CREATE|DATA_EXTEND` →
`FILE_CREATE|DATA_EXTEND|CLOSE` for one file create/write/close. Two real framing gotchas
learned (see lesson `usn_read_journal_buffer_framing`): the buffer opens with an 8-byte
next-USN cursor, and `RecordLength` is DWORD not DWORDLONG. The design is real; proceed to S1.

## The realization, grounded (read this before any build)

The "journal primitive" we were circling already exists, named, with three backends:

- **`core/foundation/ledger.py`** — `class Ledger(ABC)`: "append-and-replay". Its own docstring
  draws the exact line we re-derived: *"Store answers 'what IS the current value of X?' Ledger
  answers 'what HAPPENED, in order?'"* `emit(stream, event)` + `consume(stream, after_id)`,
  File (append-only JSONL) + Redis (streams) + Hybrid. This is the journal.
- **`core/coord/timeline.py`** (via `agent_cli.py cmd_timeline`, T211) — already joins
  **events + git + tasks** into one chronological column, and — load-bearing — prints its own
  *coverage*: *"a merged view missing a domain looks exactly like a view where nothing happened
  in it."* That is the honesty rule for the join, already shipped.
- The **NTFS USN journal** (`FSCTL_READ_USN_JOURNAL`) — the OS's own append-only,
  time-ordered, reason-coded change log. It is a *source*, not a primitive.

So the elegant simplification is not "build a journal" — it is:

> **Ingest the USN journal as a new Ledger stream, and add it as a new `timeline` domain.**
> The disk's diary becomes one more append-only stream beside the events, git, and task streams
> we already replay and join.

`find` (Everything) stays the *state* door ("where is it now"); the USN stream becomes the
*event* door ("what happened to it"); `timeline` becomes the *join* ("what happened on this
machine, in order, with the words and the disk agreeing"). Three existing organs, one new source.

## The "who did this" join — honest, not overclaimed

The USN record carries a **reason code** (create/rename/delete/data-overwrite/extend/truncate/
close/...) but **not the process**. The `timeline` join gives us the *inference*: an `fs` row at
time T lines up against an `event`/`git` row at time T (the agent's tool call, the commit). That
correlation must be **labeled "inferred from temporal co-occurrence, not asserted"** — never
fused into the row's `actor` as if the OS had told us. Same law as R1 on the eye-fuzzy spec: a
false bind costs truth, a miss costs effort.

## The plan (slices, each independently shippable)

- **S0 — spike (no repo change):** call `FSCTL_READ_USN_JOURNAL` on this box, read one page of
  `USN_RECORD_V2`, confirm (a) the ioctl works on the volume, (b) the record shape matches the
  docs (TimeStamp/Reason/FileName/FileReferenceNumber), (c) reason codes decode. Output: a
  receipts file, not a claim.
- **S1 — the reader:** `core/filesystem/usn.py` — read the journal once (or in a page loop) into
  plain dicts `{ts, reason, filename, parent_ref, file_ref}`. Pure, no network, pinned.
- **S2 — the ingest:** emit each record into the `Ledger` under a `fs` stream (the ONE append
  path; FileLedger is the durable record, Redis best-effort). Pinned: emit→consume round-trip.
- **S3 — the join:** add `fs` as a domain to `timeline.gather()`, with the same coverage honesty
  (a missing `fs` domain is PRINTED, never folded into "nothing happened"). Pinned.
- **S4 — the heat map:** group the `fs` stream by directory over a window; the churn hotspots
  fall out of the same Ledger the timeline already reads. Pinned as an aggregation, not a new
  reader.
- **S5 — the "who" lens (gated):** correlate `fs` rows with agent tool-call/commit rows on time,
  rendered with the "inferred, not asserted" label. Only after S0–S3 prove the source is real.

## Pins (RED-first, one file per slice, committed before the fix)

- S0: the spike writes a receipts file; a pin asserts it exists and names the volume + record
  count + a decoded reason code (not "ran ok").
- S1: `usn.read(...)` returns `{ts, reason, filename}` dicts; an empty journal is a DISTINCT
  result from "ioctl refused"; a refused ioctl raises with the FSCTL name, never silent-empty.
- S2: `emit` into `fs` then `consume` returns the same dicts in order; a down Redis still lands
  in File (Hybrid contract, already pinned elsewhere — reuse, don't re-pin).
- S3: `timeline.gather()` reports `fs` in coverage; when the `fs` source is absent the coverage
  line says `NOT READ: fs (...)` — never a silent zero.
- S4: heat-map aggregation over a window is a pure function of the `fs` stream (no new reader).
- S5: a "who" row carries `relation: "correlated"` and never asserts the process as fact.

## Verification process (how we know it's true, not just green)

1. **S0 receipts against reality:** the spike's decoded `Reason` flags must match a real action —
   touch a file, re-read, see `USN_REASON_DATA_OVERWRITE`/`CLOSE`. A pin that passes while the
   reason codes are garbage is the liar.
2. **Cross-source agreement:** an `fs` row must line up with what actually happened (touch →
   close → rename shows three records with the right reasons). Verify by *world*, not by the
   assertion result.
3. **Timeline coverage:** `py agent_cli.py timeline` prints `fs=N` in its coverage; kill the
   source and confirm the `NOT READ: fs` line appears (the honesty rule, exercised).
4. **The "who" join is a controlled experiment:** do a known action in one agent turn, then check
   the correlated `fs` row lines up and is *labeled* — and that a same-timestamp coincidence is
   NOT presented as causation.
5. **The principle Daniel stated, held to:** every slice checks "does the system already do
   this?" before writing — the Ledger already appends, the timeline already joins, the OS already
   logs. We add a source and a domain, never a fifth reader.
