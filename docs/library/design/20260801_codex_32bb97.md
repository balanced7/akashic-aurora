## 1. Is six the right vocabulary?

**INFERRED — Six is a useful learning ceiling, but the number does not prove that these
six categories are orthogonal.** A roster should contain visual grammars, not selection
policies.

**PROPOSED — Remove Digest as a first-class format and add Trace.** Digest answers *what
to select and how to rank it*; it does not define a unique geometry. A Board ranked by
`needs_operator`, or a set of Decision cards under the same ranking policy, already does
that job. Keep `digest` as a reusable selection lens rather than a seventh renderer.

Trace answers a structurally different question: **what actually happened in this one
run, in what order, and where did causality or evidence break?** Flow describes the
system's possible topology; Delta compares endpoints; neither preserves the observed
event sequence between them. The six grammars would therefore be:

1. Board — current state.
2. Flow — possible mechanism and breakpoints.
3. Delta — comparable endpoints.
4. Decision card — bounded choice.
5. Explainer — a pedagogical decomposition.
6. Trace — one observed execution or incident over time.

**PROPOSED — Admission rule:** every format declares `id`, `version`, the one question it
answers, its invariant payload, why the other formats cannot answer that question, owner,
introduction receipt, deprecation path, tombstone, and one accepted specimen. A seventh
does not enter alongside the six: it names the format it replaces. If Explainer cannot be
given an invariant schema, it should be the next removal candidate rather than an
ever-expanding miscellaneous bucket.

## 2. Where does `show` live?

**PROPOSED — `show` is an adapter over a pure renderer, not a new data authority.** Put
the versioned contracts and deterministic renderers in a small substrate package (for
example `core/presentation/`). Expose one CLI verb through `agent_cli.py` and one thin MCP
wrapper guarded by the existing parity check. Do not put canonical rendering logic in
`bifrost_ui.py`, and do not create one command per format.

The renderer should accept a complete presentation envelope or a durable reference. It
must not secretly query the ledger, notes, or bus based on a format name; producer doors
own data acquisition and emit the envelope. That separation keeps `show` testable and
prevents the presentation layer from becoming a second query system.

**INFERRED — CLI plus MCP is necessary but not sufficient.** It gives exec-capable seats
one door, but it does not include a seat whose allowlist or harness exposes neither. The
receiver-side path in answer 6 is therefore part of the contract, not a later integration.

## 3. What is the data contract?

**PROPOSED — Use a common versioned envelope plus a format-specific payload.** The common
envelope should carry at least:

- presentation schema version, format id, and format version;
- title, one written head, and the format payload;
- drillable source references for every material row or card;
- T121 `EpistemicView` data on every material claim, including the written head;
- an explicit render budget and overflow pointers;
- producer logical identity plus incarnation when known.

`generated_at` may be useful operational metadata, but **VERIFIED — it cannot establish
currency** under T121. A measured value is not represented by a persuasive green tile or
a Boolean `measured=true`; it is ordinarily an `observed` claim from a mechanical source
with a recorded basis receipt. An agent interpretation remains `inferred`, `proposed`, or
`self_reported` as appropriate. Authority, currency, and risk remain independent.

**PROPOSED — Ownership and change rule:** the governed format registry owns the envelope
and points to each payload schema. Compatible additions stay within a version; breaking
changes mint a new format version that coexists during a bounded migration. Unknown
versions fail visibly. Renderers may not guess fields into existence, and producers may
not strengthen missing evidence to make a card prettier.

## 4. Where does Delta's baseline live?

**PROPOSED — Neither notes nor a fat ledger record.** A baseline is an immutable,
content-addressed snapshot containing the normalized query, query/schema version, source
references, capture receipt, and payload hash. Store that snapshot through the existing
artifact/blob substrate. Append a small ledger event that points to the snapshot and
records who selected it as the baseline and why.

Notes are authored narrative with supersession semantics; using them would make
comparability depend on prose. The ledger is the right authority for the *selection
event*, but embedding every baseline payload in it would turn an event log into a snapshot
store. This split uses existing authorities rather than minting a new one.

**PROPOSED — Comparability gate:** Delta runs only when baseline and current observation
share the same normalized query and compatible schema, or when a named, tested migration
exists. Otherwise it renders `UNKNOWN / not comparable`; it must not coerce different
measurements into a confident arrow. Current state is regenerated live. The baseline is
preserved because history cannot be regenerated from the present.

## 5. Does this reduce reading or relocate it?

**INFERRED — Without an exit budget, it relocates the wall.** The older draft's strongest
point is that selection beats encoding. A beautiful page containing the same unranked
material is still the same burden.

**PROPOSED — Enforce the budget at the complete rendered seam.** The schema permits one
written head, bounded visible items, bounded text per item, and drill pointers for the
rest. The renderer rejects or overflows excess prose instead of placing nine hundred words
below the shape. Numeric limits should be ratified from measured specimens, but the
mechanism must exist before the first default-on format: count the whole artifact, not
just its generated body.

The written head is not epistemically exempt. It carries its author, claim kind, basis,
currency, and risk like every other material claim. A six-week-old recommendation may
remain valuable, but it must not look current merely because the live body regenerated.

**PROPOSED — Narrow the rule:** replace “No reading surface is hand-written” with:

> No surface that claims current system state may rely on hand-written state. It must be
> regenerated or render currency as UNKNOWN. Authored history, rationale, and teaching
> may remain hand-written when labeled, sourced, and placed behind the bounded overview.

The original absolute rule would classify durable reasoning and incident narratives as
defects merely because they are documents. Staleness is a claim/property mismatch, not a
file-extension property.

## 6. Does `show` reach Kimi?

**VERIFIED — As presently specified, not necessarily.** A CLI verb plus an MCP twin does
not prove that a no-exec harness has either door. The proposal's “every seat gets it free”
claim therefore lacks its own acceptance receipt.

**PROPOSED — Render at the receiver.** A no-exec seat should be able to send the typed
presentation envelope through its existing structured Bifrost tool (for example under
`meta.presentation`). The receiving UI or exec door validates and renders it. The CLI is
the reference/dogfood renderer, not a prerequisite for participation. Invalid envelopes
return a bounded validation error; they do not silently fall back to prose or invent
epistemic status.

Acceptance must include a real no-exec vertical: Kimi creates one instance of every
format, another seat receives the same envelope, and the rendered substance matches the
reference output without Kimi running a shell command. Until that passes, the mechanism
excludes a named consumer and is wrong as specified.

## Sequence and ratification recommendation

**PROPOSED — Do not build Delta first.** Delta is the most valuable missing view, but it
is also the only format whose prerequisite changes durable state. First freeze the common
envelope, T121 provenance binding, roster admission rule, and receiver-side no-exec path.
Then productize Board as the reference renderer because a Board specimen has already
cleared Daniil's comprehension bar. Build Delta immediately after its baseline contract
passes pre-registered comparability and kill tests.

My ratification vote is therefore **YES to a governed presentation vocabulary; NO to the
current six and mechanism unchanged**. The proposal becomes safe when selection is
separate from geometry, provenance is typed rather than decorative, current-state claims
cannot be hand-written, and execution capability is not the price of speaking visually.

### The acceptance property is stronger than reading reduction

**VERIFIED —** The operator says the missing surface obscures the *scale and effort* of
the work, not merely its wording. The original Q5 test — “did this reduce reading?” — is
therefore necessary but insufficient.

**INFERRED —** A shorter surface can still fail completely if it makes a large effort look
small, or if it reports a result without teaching why the result matters. Compression is
an input metric. Perception and understanding are the outcome.

**PROPOSED — Re-bar every specimen with a cold-viewing check.** After seeing only the
bounded overview, Daniil should be able to state:

1. the magnitude of the state or change;
2. what evidence of effort is present and what effort remains unknown;
3. why the result matters to his system or next choice; and
4. where he would drill when one of those answers is uncertain.

Those questions and their scoring must be registered before a default-on build. Word
count remains a budget, not the success criterion.

### Effort is a dimension, not a seventh format or a decorative score

**PROPOSED — Keep Trace in the roster, but do not make it the sole “effort format.”**
Trace makes attempts, reversals, failures, and causal sequence legible; that is evidence
for its distinct grammar. But effort cuts across the vocabulary:

- Board shows the scale and distribution of work now.
- Delta shows what the work bought.
- Trace shows the path, including failed or abandoned branches.
- Explainer teaches what the work means and checks whether that teaching landed.

The common envelope should therefore allow typed `effort_evidence` on material items.
Examples include elapsed intervals, attempts, participating seats, changed artifacts,
tests or drills, and failed branches **only when each has a drillable receipt**. These are
observations and proxies, not interchangeable units. No renderer may collapse them into a
single “effort score” unless a separately governed and validated model exists. Missing
effort evidence renders `UNKNOWN`; message volume, token spend, or elapsed time alone must
not silently become a claim about difficulty or value.

**PROPOSED — My Digest/Trace swap stands.** The new material strengthens the need to show
process, but it does not turn ranking policy into a visual grammar. `digest` remains the
cross-format selection lens that chooses what Daniil needs after an absence; Trace remains
the shape for one observed path.

### Explainer now has a defended invariant

**PROPOSED — This addendum supersedes my earlier statement that Explainer should be the
next removal candidate if its schema stayed vague.** Daniil has now named the didactic
feedback loop directly, so Explainer earns its slot if it carries a checkable invariant:

1. concept boundary — what one thing is being taught;
2. parts and relationship — the real decomposition, not a metaphor alone;
3. concrete Aurora instance — where it exists in his system;
4. why it matters to him — the consequence in his own operating frame; and
5. one bounded check for understanding whose answer informs the next explanation.

Without item 5 it is an explanation, not a feedback loop. The receiver must preserve the
answer as input to the next teaching turn without treating agreement as comprehension.

### Sequencing judgment

**INFERRED — The new evidence strengthens, rather than reverses, my Board-first reference
slice.** The receipt that changed the premise came from a rendered Board. That is direct
operator evidence for one grammar already clearing the perception bar. Bottle that
accepted instance into the common contract first; then build Delta as soon as its durable
baseline and comparability gate are ready.

Delta remains the highest-value missing view, but “most wanted” does not remove its unique
substrate dependency. If a blinded Board-versus-Delta trial shows Delta communicates scale,
effort, and payoff materially better while its baseline gate is ready, that result would
change my sequencing vote. Until then, the observed success outranks the hypothesized one.
